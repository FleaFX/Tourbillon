Chapter 5

Changing the copies

In three sentences

The copies of a group can change while the group keeps running: one copy is added or removed at a time, through an entry in the log itself. A new copy first catches up as a learner, which does not vote and does not count for the majority, and only becomes a full copy once it has everything, which Tourbillon takes care of by itself. The leader can also hand its role to another copy on purpose, and a copy that was away cannot disturb the group when it comes back.

Why the copies change

Machines come and go. A machine is added to share the work, one is taken away, one breaks and does not come back. Each time, some groups need a copy on another machine. Which machines carry which copies is the user's decision: Remontoire, for example, spreads its partitions over its machines by itself. Tourbillon gives the means to change the copies safely; it never decides on its own.

One change at a time, through the log

Which copies a group has is itself kept in the log. To change it, the user proposes a special entry to the leader: "from now on, the copies are these". That entry is copied and accepted like any other, so every copy learns about the change in the same place in the log.

Each such entry adds or removes exactly one copy, and the leader takes a next change only once the previous one is accepted. The reason: with one copy more or less, every majority of the old copies and every majority of the new copies still share at least one copy. So the old and the new copies can never choose two different leaders at the same time.

Adding a copy: first a learner

A new copy starts empty. If it would count for the majority straight away, the group would be weaker for a while, not stronger. An example:

  1. A group has copies on machines 1, 2 and 3. It needs 2 of 3, so one machine may fail.
  2. A copy on machine 4 is added, and counts at once. Now the group needs 3 of 4.
  3. Machine 4 is still empty and stores nothing new until it has caught up. So in practice, machines 1, 2 and 3 must all answer.
  4. Machine 3 fails. Only 1 and 2 are left that can store entries: 2 of 4, no majority. The group stops, although only one machine failed.

So a new copy first joins as a learner. A learner gets everything the other copies get, the snapshot first if the start of the log was already let go (chapter 3), then the entries. But it does not vote, and it does not count for the majority: in the example, the group keeps needing 2 of 3 while machine 4 catches up.

The user does not see this in-between step. It simply asks the leader: "add a copy on machine 4". Tourbillon adds it as a learner, follows how far it has caught up, and once the learner misses no more than what the leader hands on in one go, Tourbillon makes it a full copy, with a second change entry. Only then does the user get "done". The user decided that the copy comes; Tourbillon only chooses the moment, because it is the one that knows how far the learner is. If the learner does not catch up, for example because its machine is too slow, it simply stays a learner, and the user can remove it again. How far every copy is, the user can always see in the measurements (chapter 6).

Removing and moving a copy

Removing a copy is one change entry. Once it is accepted, the removed copy no longer takes part, and the user can drop it from its machine, which deletes its files. If the leader itself is removed, it keeps leading until the change is accepted, and then steps down, so that the others choose a new leader among themselves.

Moving a copy from one machine to another is two steps one after the other: add a copy on the new machine, and once that is done (it caught up as a learner and became a full copy), remove the old copy. The group keeps running all the time, and never has fewer full copies than before.

A copy whose disk was damaged (chapter 2), or that is on a machine that will not come back, is replaced the same way: remove it, and add a new copy elsewhere. When to do that is the user's choice; Remontoire, for example, first waits a set time, so that a restart costs nothing extra.

Sending a snapshot

A learner, or a copy that fell far behind, may need the snapshot of the user (chapter 3). The user on the leader hands it to Tourbillon as a list of files; Tourbillon sends them in pieces, and the user on the other machine starts from them. If the sending breaks off, it starts again from the first piece. MSSP's snapshot can be large and take a while; meanwhile the group goes on as usual.

Handing over leadership

Sometimes the user wants another copy to lead: to spread the leaders of many groups evenly over the machines, or before a machine restarts for an update. Waiting until the leader is gone would cost a pause and a few unknown answers (chapter 4). So the user can ask the leader to hand over to a chosen copy:

  1. The leader stops taking new proposals; they are refused, and the user proposes them again at the new leader.
  2. The leader makes sure the chosen copy has every entry it has.
  3. The leader tells the chosen copy to start an election at once. The chosen copy asks for votes with a mark: "the leader asked me". It wins, because its log is complete, and leads.

The mark is needed because the other copies still hear the leader, and would otherwise refuse to help start an election (see below). It only drops that one question; the usual rules of chapter 4 still hold: one vote per term, and only for a copy whose log is at least as complete.

The pause is much shorter than after a failure. If the chosen copy does not take over within a short time, the old leader takes proposals again.

A copy that was away cannot disturb

A copy that is cut off from the others hears no leader, and would start one election after another, each with a higher term. When it comes back, that high term would make the real leader step down, for nothing: every copy that sees a higher term must take it over, and a leader that sees one must step down.

The copy cannot simply undo an election that got no answer. A real election starts by raising its own term, storing it on disk and voting for itself, and only then asking the others. Maybe a request did arrive somewhere and only the answer got lost. If the copy went back to its old term, it could later vote a second time in the same term, and two leaders would be possible. So a term never goes down, and after a minute of trying, the copy is many terms ahead.

So before a real election, a copy first asks a trial question, which changes nothing: the asking copy does not raise its term, and the copies that answer store no vote. Only when a majority answers "yes" does it start the real election. An example:

  1. Machine 3 is cut off for a minute. Machines 1 and 2 go on, with machine 1 leading in term 6.
  2. Machine 3 hears nothing. It asks the trial question: "would you vote for me in term 7?" Nobody answers, so it does not raise its term. It asks again later.
  3. The network is back. Machine 3 asks the trial question again. Machine 2 answers "no": it hears its leader just fine. That also helps when the network only half works: if machine 3 cannot hear the leader but machine 2 can, machine 2 still says "no". So machine 3 still does not raise its term, and soon hears from machine 1 itself.

The same holds for a copy that was removed but keeps running: it gets "no" from every copy that still hears the leader, and can never make it step down.

The trial question also changes the election example of chapter 4 a little. Machine 3 asks it first, and machine 2 answers "no", because its log has entry 800: so machine 3 does not even raise its term. Then machine 2 asks the trial question, machine 3 says "yes", and machine 2 leads in term 5 instead of 6, with entry 800.

What must always be true
  • The copies of a group change by one copy at a time, through an accepted entry, and a next change waits until the previous one is accepted.
  • A new copy is first a learner: it does not vote and does not count for the majority until it has caught up.
  • Adding, removing or moving a copy never loses an accepted entry.
  • The group keeps running during a change, as long as a majority of its full copies is there.
  • Handing over leadership never leads to two leaders that can get entries accepted.
  • A copy that hears a leader does not help another copy start an election, unless the leader itself asked for that election.

What Tourbillon does not do here

  • Tourbillon does not decide which machines carry which copies, when a broken copy is replaced, or which copy should lead.
  • Tourbillon does not change two copies in one step, not even to go faster.
  • Tourbillon never adds or removes a copy on its own. It does make a learner a full copy by itself, but only for a copy the user asked for.

Words used in this chapter

Change entry
A special entry that says which copies a group has from then on. It adds or removes one copy.
Learner
A new copy that catches up: it gets every entry, but does not vote and does not count for the majority.
Full copy
A copy that votes and counts for the majority.
Trial question (pre-vote)
A question before a real election, "would you vote for me?", that changes nothing: no term goes up and no vote is stored.
Hand over
Let the leader pass its role to a chosen copy on purpose, with only a short pause.
