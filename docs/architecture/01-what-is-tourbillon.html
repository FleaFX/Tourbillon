Chapter 1

What is Tourbillon

In three sentences

Tourbillon keeps a log on disk that survives a crash, and copies it over several machines so that they agree on what is in it, even when one of them fails. A program hands an entry to Tourbillon; once Tourbillon calls it accepted, the entry is safe, and every machine gets it at the same place in the same order. Tourbillon does not know what the entries mean: the program that uses it turns them into its own state.

The problem

Some programs must never forget what they were told. A replicated database must keep every change it confirmed; an event store must keep every event it accepted; a message broker must keep every message until it is delivered. Such a program needs two things:

  • A place where written means written. Once it has said "stored", a crash or a power failure must not take it back.
  • Agreement between machines. With several machines, so that one can fail without anything stopping, they must agree on what was written and in which order, also when a machine fails halfway or the network between them breaks.

Both are hard to get right, and a mistake rarely shows: everything works, until one day a power failure or an unlucky moment loses something that was called safe. Two programs need both: the event store MSSP and the message broker Remontoire. So the hard part is built once, tested hard, and shared: that is Tourbillon.

What Tourbillon does

A program that uses Tourbillon, the user, does not write to disk or talk to other machines itself. It hands its entries to Tourbillon, and gets back the accepted entries, in order, to build its state from.

  1. Propose. The user hands an entry to Tourbillon: a piece of bytes, such as an event to store or an acknowledgement of a message.
  2. Accepted. Tourbillon writes the entry to disk, on most of its machines when there are several, and only then answers "accepted", with the number of the entry in the log. If that is not possible, the user gets an error, and nothing was accepted.
  3. Apply. On every machine, Tourbillon hands the accepted entries to the user, in the order of the log. The user applies them to its own state. Because every machine gets the same entries in the same order, they all end up with the same state.

One machine is enough to use Tourbillon. It then keeps one log, without copies, and every promise of chapter 2 still holds. More machines only add that one of them may fail (chapter 4).

What must always be true
  • An entry Tourbillon called accepted is not lost by a crash or a power failure, and not by the failure of fewer than half of the machines.
  • An accepted entry never changes, and keeps its number in the log.
  • Every machine hands the user the same accepted entries, in the same order, and never an entry that was not accepted.
  • An accepted entry stays until the user says it may go (chapter 3).

Who uses it

  • Remontoire, the message broker, keeps every partition of a stream as a log of its own in Tourbillon, and also its register: what it knows about its machines, streams and groups. The messages themselves stay in the log until the retention of their stream lets them go.
  • MSSP, the event store, keeps one log for all its events. Its own storage on disk is built from that log. MSSP moves onto Tourbillon after its own architecture has been thought through again.

What Tourbillon is not

  • Not a database. Tourbillon never reads what is in an entry, and cannot be searched. Finding things is the job of the user's state.
  • Not a product you install. It is a library. The user builds it in, and the application that hosts the user decides where it runs.
  • Not a network server. Tourbillon does not open a network port. The traffic between its machines runs through endpoints that the host puts in its own web application, and the host protects that traffic.
  • Not a judge of what may go. Tourbillon has no retention rules of its own: the user decides up to where the start of the log may be removed.
  • Not a protection against a machine of its own that lies. Tourbillon trusts every copy of a group: a machine that takes part and does not follow the rules can break every promise in this book. The host makes sure that only its own machines can take part (chapter 6).

The name

A tourbillon is a small turning cage in a mechanical watch. It carries the part that sets the pace, and by turning it all the time, it evens out the small errors that would otherwise make the watch run fast or slow. Tourbillon does the same for its users: machines fail and networks break, but the user keeps one steady log. Remontoire, too, is named after a part of a watch.

Words used in this book

User
The program that uses Tourbillon, such as MSSP or Remontoire.
Entry
One piece of bytes the user hands to Tourbillon. Tourbillon never reads what is in it.
Log
The entries, one after the other, in the order Tourbillon accepted them.
Index
The number of an entry in its log: 1, 2, 3 and so on.
Propose
Hand an entry to Tourbillon, asking it to add the entry to the log.
Accepted
Safe: an accepted entry survives a crash, a power failure and the failure of fewer than half of the machines.
State
What the user builds from the accepted entries, such as the events of a stream or how far a reader got.

The next chapters define more words, as they are needed.
